1시작하기

주소

구분주소누가 쓰나요
홈페이지https://student378.github.io/yuhandormitory/학생·방문자
관리자https://student378.github.io/yuhandormitory/admin.html담당 직원

파일 보관소https://github.com/student378/yuhandormitory담당 직원 (GitHub 계정 필요)

관리자 페이지는 로그인이 없습니다. 누가 열어도 편집은 되지만, 그 내용은 그 사람 브라우저 안에만 남고 홈페이지는 바뀌지 않습니다. 홈페이지를 실제로 바꾸려면 GitHub 저장소에 파일을 올려야 하므로, 저장소 권한이 있는 사람만 반영할 수 있습니다.

화면 구성

  • 왼쪽 메뉴: 고칠 영역을 고릅니다. (기본 정보, 메뉴·페이지, 메인 비주얼, 퀵메뉴, 팝업·알림존, 게시판, 주간식단표, 생활관 일정, 연결·백업)
  • 미리보기: 고친 내용이 홈페이지에 어떻게 보이는지 새 창으로 보여줍니다. 화면 맨 위에 노란 띠가 있으면 미리보기 화면입니다.
  • 파일 내려받기 (숫자): 고친 내용이 담긴 파일을 내려받습니다. 숫자는 바뀐 파일 개수입니다.
  • 로컬 편집 모드 표시: 지금 고친 내용이 이 브라우저에만 있다는 뜻입니다.
자동 보관 고친 내용은 브라우저에 자동으로 보관되어 창을 닫았다 열어도 남아 있습니다. 다시 열면 "이어서 편집할까요?"라고 묻습니다. 단, 다른 PC나 다른 브라우저에서는 보이지 않습니다.

2홈페이지에 반영하는 방법

전체 흐름

STEP 1수정관리자에서 내용 고치기
STEP 2미리보기보이는 모습 확인
STEP 3내려받기data 파일 받기
STEP 4GitHub에 올리기1~2분 뒤 반영

STEP 3 · 파일 내려받기

[파일 내려받기]를 누르면 바뀐 파일만 내려받아집니다. 파일 이름은 정해져 있습니다.

파일담긴 내용
site.js기본 정보, 메뉴·페이지 본문, 메인 비주얼, 퀵메뉴, 팝업·알림존, 생활관 일정
posts.js게시판과 모든 게시글
meals.js주간식단표
주의 브라우저가 같은 이름의 파일을 site (1).js처럼 바꿔 저장할 수 있습니다. 올리기 전에 이름이 정확히 site.js · posts.js · meals.js인지 확인하고, 다르면 이름을 고쳐 주세요.

STEP 4 · GitHub에 올리기 GitHub 계정으로 로그인한 상태에서

  1. 저장소의 data 폴더를 엽니다.
  2. 오른쪽 위 Add file → Upload files를 누릅니다.
  3. 내려받은 파일을 화면에 끌어다 놓습니다. 같은 이름의 파일은 자동으로 덮어씁니다.
  4. 아래 Commit changes 칸에 무엇을 고쳤는지 짧게 적고(예: 10월 3주 식단 등록) Commit changes를 누릅니다.
  5. 1~2분 뒤 홈페이지를 새로고침하면 반영되어 있습니다. 바로 안 바뀌면 Ctrl + F5로 강력 새로고침하세요.
꼭 지켜 주세요 내려받은 뒤에는 바로 GitHub에 올리세요. 내려받으면 브라우저 보관본이 지워집니다. 올리기 전에 관리자를 다시 열면 홈페이지에 있는 예전 내용으로 시작하므로, 그 상태로 고치고 내려받으면 앞서 고친 내용을 덮어쓰게 됩니다.
여러 명이 관리할 때 두 사람이 동시에 고치면 나중에 올린 파일이 앞사람의 수정을 덮어씁니다. 담당자를 정하거나, 고치기 전에 관리자를 새로 열어 최신 내용으로 시작하세요.

(선택) 버튼 한 번으로 반영하기 GitHub 토큰 연결

매번 파일을 올리는 게 번거로우면 관리자 연결 · 백업 메뉴에서 GitHub 토큰을 연결하세요. 버튼 이름이 [저장 · 배포]로 바뀌고, 누르면 STEP 3~4가 자동으로 처리됩니다. 사진·첨부파일도 관리자에서 바로 올라갑니다.

  • 토큰 발급: GitHub → Settings → Developer settings → Fine-grained tokens → 이 저장소만 선택 → Contents: Read and write
  • "이 브라우저에 토큰 기억하기"는 개인 PC에서만 켜세요. 공용 PC에서는 사용 후 [연결 해제]를 누르세요.
  • 토큰이 유출되면 GitHub 설정에서 바로 삭제(Revoke)하고 새로 만드세요.

3메뉴별 사용법

기본 정보

  • 대학 이름 · 사이트 이름: 로고 옆 글자와 브라우저 탭 제목에 쓰입니다.
  • 로고 이미지: 비워 두면 집 모양 기본 로고와 글자가 나옵니다. 투명 배경 PNG, 높이 100px 정도를 권장합니다.
  • 대표 색상: 메뉴 강조, 버튼, 식단 상자 등 사이트 전체의 기본 색이 바뀝니다.
  • 메인 게시판 탭: 메인 화면 "공지사항" 영역에 탭으로 보여줄 게시판을 고릅니다.
  • 문의 안내 · 상단 링크 · 하단 링크 · 관련 사이트: [+ 추가]로 늘리고 ▲▼로 순서를 바꿉니다.

메뉴 · 페이지

종류쓰임내용 관리
일반 페이지인사말, 입사안내 같은 글 페이지[내용 편집] 버튼
게시판공지사항, 자료실 등게시판 메뉴
주간식단표식단표 화면주간식단표 메뉴
생활관 일정월간 달력 화면생활관 일정 메뉴
외부 링크입사신청 사이트, 구글 폼 등주소 입력
  • ID는 주소에 쓰입니다(예: #/m/greeting). 영문 소문자·숫자·하이픈만 쓰고, 다른 곳에서 링크한 메뉴의 ID는 바꾸지 마세요.
  • 지도/영상: 네이버·카카오 지도나 유튜브의 "퍼가기(HTML)" 코드를 붙여넣습니다.
  • 한글(HWP)·워드에서 복사해 붙이면 글꼴·색이 섞일 수 있습니다. 해당 부분을 선택하고 [서식 지우기]를 누르세요.
  • 편집기에서 [적용]을 눌러야 내용이 반영됩니다. 그다음 [파일 내려받기]까지 해야 홈페이지가 바뀝니다.
메뉴에 없는 페이지 개인정보처리방침처럼 하단 링크로만 여는 페이지는 화면 아래쪽 "메뉴에 없는 페이지"에서 관리합니다.

메인 비주얼

  • 배경 이미지를 비우면 배경색(그라데이션)이 쓰입니다. 사진 올리는 방법은 4장을 보세요.
  • 사진 위에 흰 글씨가 올라가므로 왼쪽이 어둡거나 단순한 사진이 잘 어울립니다. 사진에는 자동으로 약간 어두운 막이 깔립니다.
  • 제목은 Enter로 줄을 바꿀 수 있습니다. 두 줄 이내를 권장합니다.
  • 슬라이드는 6초마다 넘어갑니다. 3~4장이 적당합니다.

퀵메뉴

  • PC에서는 한 줄 8개, 모바일에서는 4개씩 두 줄로 보입니다. 4개, 8개로 맞추면 빈칸이 없습니다.
  • 링크 칸을 누르면 사이트 안 페이지 주소 목록이 나옵니다. 외부 사이트는 https://로 시작하는 주소를 넣으면 새 창으로 열립니다.

팝업 · 알림존

  • 시작일 ~ 종료일 동안만 팝업이 뜹니다. 기간이 지나면 지우지 않아도 자동으로 사라집니다.
  • 잠시 내리려면 사용 체크를 끄세요.
  • 팝업은 이미지 또는 내용(HTML) 중 하나 이상 넣습니다. 이미지만 쓰면 글자가 작게 보일 수 있으니 핵심 문구는 내용에도 적어 주세요.
  • 방문자가 "오늘 하루 열지 않기"를 누르면 그날은 그 사람에게 다시 뜨지 않습니다.

게시판

  • 상단 고정(공지)을 켜면 목록 맨 위에 "공지" 표시와 함께 고정됩니다. 고정 글은 2~3개 이내로 유지하세요.
  • 등록일로 정렬됩니다. 등록일이 7일 이내인 글에는 빨간 N 표시가 붙습니다.
  • 첨부파일: [+ 파일 업로드]로 넣습니다. 방법은 4장과 같습니다.
  • 갤러리형 게시판(생활관 소식)은 대표 이미지가 목록 사진이 됩니다. 비우면 본문 첫 사진을 씁니다.
  • 게시판 추가: 화면 아래 "게시판 추가 · 설정"에서 만든 뒤, 메뉴 · 페이지에서 종류를 "게시판"으로 한 메뉴를 만들어 연결합니다.

주간식단표

  1. [◀ 이전 주] [다음 주 ▶]로 입력할 주를 고릅니다.
  2. 칸에 직접 입력하거나, 아래 엑셀에서 한번에 붙여넣기를 씁니다.
  3. 엑셀 붙여넣기: 엑셀에서 조식·중식·석식 3행 × 월~일 7열 범위만(제목 줄 제외) 복사해 붙여넣고 [붙여넣은 내용 적용]을 누릅니다. 한 칸 안의 여러 줄(Alt+Enter)도 그대로 들어갑니다.
  4. 메뉴가 비슷한 주는 [지난주 식단 복사] 후 바뀐 칸만 고치면 빠릅니다.
팁 식단만 바꿨다면 내려받는 파일은 meals.js 하나뿐입니다.

생활관 일정

  • 메인 화면에는 오늘 이후 일정 4개가 나오고, "생활관 일정" 메뉴에서는 달력으로 보입니다.
  • 입력 순서와 상관없이 날짜순으로 표시됩니다. 관리 화면을 정리하려면 [날짜순 정렬]을 누르세요.

연결 · 백업

  • 전체 백업 내려받기: 모든 내용을 파일 하나로 받습니다. 큰 개편 전에 받아 두세요.
  • 백업 파일 불러오기: 백업 시점으로 되돌립니다. 그다음 [파일 내려받기] → GitHub에 올리기를 해야 홈페이지에 반영됩니다.
  • 보관된 수정 내용 버리기: 브라우저에 보관된 수정 내용을 버리고 지금 홈페이지 내용으로 다시 시작합니다.
  • GitHub에는 올린 기록이 모두 남습니다. 저장소의 History에서 예전 파일을 내려받아 되돌릴 수도 있습니다.

4사진 · 파일 올리기

올리는 순서 로컬 편집 모드 기준

  1. 사진이 들어갈 칸(배경 이미지, 로고, 팝업 이미지 등)이나 편집기의 [업로드]·[이미지] 버튼을 누르고 사진을 고릅니다.
  2. 관리자가 사진을 자동으로 줄여서 새 이름(예: 20261011-142122-IMG_2041.jpg)으로 내려받고, 칸에는 uploads/20261011-142122-IMG_2041.jpg가 자동으로 채워집니다.
  3. 내려받은 사진을 저장소의 uploads 폴더에 Add file → Upload files로 올립니다. 파일 이름은 바꾸지 마세요.
  4. 평소처럼 [파일 내려받기] → data 폴더에 올리기를 합니다. 사진과 data 파일은 한 번에 같이 올려도 되지만 폴더가 다르니 각각 올려 주세요.
자동 줄이기 가로 1920px보다 크거나 400KB가 넘는 사진(JPG·PNG·WEBP)은 가로 1920px, JPEG 품질 85%로 줄입니다. 휴대폰 사진(3~6MB)이 보통 0.3~0.6MB가 됩니다. 시험해 보니 5.4MB 사진이 553KB가 되었습니다.
편집기에 붙여넣기 캡처한 화면을 편집기에 Ctrl+V로 붙여넣거나 사진을 끌어다 놓아도 같은 방식으로 줄여서 내려받습니다. 내려받은 파일을 uploads 폴더에 올리는 것만 잊지 마세요.
미리보기에서 사진이 안 보이나요? 미리보기는 홈페이지에 올라간 파일을 읽습니다. 사진을 uploads 폴더에 올리고 1~2분 지나면 보입니다.

5용량 검토

결론: 생활관 홈페이지 규모에서는 문제 없습니다

관리자의 자동 줄이기를 거쳐 사진을 올리면, 1년에 사진을 수백 장 올려도 무료 한도의 몇 %밖에 쓰지 않습니다. 다만 아래 주의할 점 네 가지는 지켜 주세요.

코드 + 예시 데이터

줄인 사진 1장0.2~0.6MB

원본 3~6MB 기준

1GB에 담기는 사진약 2,000장 이상

배포 횟수시간당 10회 (권장 한도)하루 몇 번여유
posts.js 크기-글 1개 약 1~3KB → 연 200개면 약 0.5MB수년 뒤 정리

전송량 계산: 메인 화면 첫 방문은 코드·데이터 약 0.3MB와 메인 비주얼 사진 3장(약 1.2MB)입니다. 두 번째 방문부터는 브라우저에 저장된 파일을 다시 쓰므로 훨씬 적습니다. 학생 500명이 매일 들어와도 월 2~3GB 수준입니다.

주의할 점

  1. 원본 사진을 GitHub에 바로 올리지 마세요. 반드시 관리자의 [업로드]·[이미지] 버튼으로 줄인 파일을 올리세요. 원본 5MB 사진이 메인 비주얼에 3장 있으면 방문할 때마다 15MB를 받아 휴대폰에서 매우 느립니다.
  2. 올렸다 지운 파일도 용량을 차지합니다. GitHub는 모든 기록을 보관하므로 삭제해도 저장소 크기는 줄지 않습니다. 큰 파일은 신중히 올리세요.
  3. 게시글은 모든 방문자가 한꺼번에 받습니다. 게시글은 posts.js 한 파일에 들어 있습니다. 글이 1,000개를 넘거나 파일이 2MB를 넘으면 [전체 백업 내려받기]로 보관한 뒤 오래된 글을 지우세요. 사진은 따로 저장되므로 글 수에는 영향을 주지 않습니다.
  4. 동영상은 유튜브로. 동영상 파일은 한도를 빠르게 쓰고 재생도 느립니다.
용량 확인 방법 GitHub 저장소 화면 오른쪽 위 프로필 → Settings → Repositories에서 저장소 크기를 볼 수 있습니다. 500MB를 넘으면 오래된 사진 정리를 검토하세요.

6문제 해결

GitHub에 올렸는데 홈페이지가 안 바뀌어요.
배포에 1~2분 걸립니다. 기다린 뒤 Ctrl + F5(맥은 Cmd + Shift + R)로 강력 새로고침하세요. 그래도 그대로면 올린 파일 이름이 정확히 site.js · posts.js · meals.js인지, data 폴더 안에 올렸는지 확인하세요. 저장소의 Actions 탭에서 배포가 끝났는지(초록 체크)도 볼 수 있습니다.
홈페이지에 "데이터를 불러오지 못했습니다"가 떠요.
data 파일이 잘못 올라갔을 때 나옵니다. 저장소의 data 폴더에서 해당 파일의 History를 열어 직전 버전을 내려받아 다시 올리거나, 관리자 [백업 파일 불러오기]로 되돌린 뒤 다시 내려받아 올리세요. data 파일을 메모장으로 직접 고치는 것은 권하지 않습니다.
사진이 엑스박스로 나오거나 미리보기에서 안 보여요.
관리자에서 내려받은 사진을 아직 uploads 폴더에 올리지 않았거나, 올리면서 파일 이름이 바뀐 경우입니다. 칸에 적힌 이름(uploads/ 뒤 부분)과 저장소에 올라간 파일 이름이 글자 하나까지 같은지 확인하세요.
어제 고친 내용이 관리자에 없어요.
수정 내용은 고친 PC의 그 브라우저에만 보관됩니다. 다른 PC나 다른 브라우저, 시크릿 창에서는 보이지 않습니다. 또 [파일 내려받기]를 하면 보관본이 지워지고, 그 뒤 관리자를 열면 홈페이지에 올라가 있는 내용으로 시작합니다. 내려받은 파일을 GitHub에 올렸는지 확인하세요.
잘못 올렸어요. 되돌릴 수 있나요?
네. GitHub 저장소에서 파일을 열고 History를 누르면 올린 기록이 모두 나옵니다. 되돌릴 시점의 파일을 열어 내려받은 뒤 다시 올리면 됩니다. 큰 개편 전에는 관리자 [전체 백업 내려받기]도 받아 두세요.
팝업이 안 떠요.
사용 체크가 켜져 있는지, 오늘이 시작일~종료일 안에 있는지 확인하세요. 본인이 "오늘 하루 열지 않기"를 눌렀다면 그날은 그 브라우저에서 뜨지 않습니다. 시크릿 창으로 확인해 보세요. 팝업은 메인 화면에서만 뜹니다.
한글 파일에서 붙여넣었더니 글꼴이 이상해요.
편집기에서 해당 부분을 선택하고 [서식 지우기]를 누르세요. 표는 HWP 표보다 편집기의 [표] 버튼으로 새로 만드는 편이 모바일에서 깔끔하게 보입니다.
관리자 주소를 학생이 알면 위험하지 않나요?
관리자에서 고쳐도 그 사람 브라우저 안에서만 바뀌고, 홈페이지는 GitHub 저장소에 파일을 올려야 바뀝니다. 저장소 권한(또는 토큰)이 없는 사람은 홈페이지를 바꿀 수 없습니다. 토큰을 연결해 쓰는 경우 공용 PC에서는 토큰을 기억하지 말고 사용 후 [연결 해제]를 누르세요.
